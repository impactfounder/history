## 0. 왜 바꾸는가

시간축은 세로 한 방향이다(위=과거, 아래=현대, §5-1). 그런데 0.3은 그 축을 훑는 가장 익숙한 입력인 **휠을 줌에 배정**하고 시간 이동을 드래그로 보냈다. 창이 작을수록 "일단 내려서 본다"가 되지 않는다. 대표가 작은 창에서 검토한 결과가 이 판단이다.

전환의 실익은 UX 하나가 아니다. 0.3 §5-5는 스스로 이렇게 적었다:

> 이 모델의 비용: 네이티브 스크롤을 쓰지 않으므로 관성·러버밴드·접근성을 직접 구현한다. (`PRD.md:151`)

**시간축을 브라우저의 스크롤 컨테이너 그 자체로 만들면 이 비용이 통째로 사라진다.** 관성·러버밴드·스크롤 앵커링·키보드 이동·스크롤바·접근성 트리를 전부 브라우저가 준다. 트랙패드와 휠을 구분해야 했던 문제(§11 C-5)도 원인째 없어진다.

바꾸지 않는 것: 축 방향, 축의 선형성, 지도 없음, 기본 4열, 관점별 명칭, 3개 의미 레벨과 스케일 경계, 데이터 모델 본체.

## 1. §5-5 전면 교체 — 현행 135–152행

아래 본문으로 절 전체를 갈아 끼운다.

### 5-5. 조작: 스크롤 = 시간 이동, Ctrl+휠·핀치 = 줌

시간축은 **브라우저의 세로 스크롤 컨테이너 그 자체**다. 축을 훑는 동작은 전부 브라우저에 맡기고 우리는 줌만 만든다. 작은 창에서도 "일단 내려서 본다"가 되어야 한다는 것이 이 결정의 이유다(대표, 2026-09-04. A-11 정정).

| 입력 | 동작 |
|---|---|
| 휠 · 트랙패드 두 손가락 | 시간 이동. 관성·러버밴드·스크롤바 전부 브라우저 기본 |
| Ctrl + 휠, 트랙패드 핀치 | 줌. **앵커 아래 연도 고정**(§5-5A). `preventDefault`로 브라우저 페이지 줌을 막는다 |
| 더블클릭 | 그 지점 중심 한 레벨 확대 |
| `+` / `−` 키, 하단 줌 바 | 뷰포트 중앙 기준 줌. `0` = 기본 스케일 |
| ↑↓ · PageUp/PageDown · Home/End | 시간 이동. 구현 없이 브라우저가 처리 |
| ← → | 열 포커스 이동. Enter = 상세 |
| Shift + 휠 | 가로 스크롤(브라우저 기본). 열이 뷰포트보다 넓을 때만 의미 |
| 시대 레일 클릭·드래그 | `scrollTo`로 점프 / 뷰포트 창 끌기(§5-10) |
| 폰: 세로 드래그 | 시간 이동. 관성 포함, 브라우저 기본 |
| 폰: 핀치 | 줌. 두 손가락 중심 연도 고정 |
| 폰: 가로 스와이프 | 두 번째 열 전환(가로 우세 제스처로 축 잠금) |

- **얻는 것.** 관성·러버밴드·스크롤 앵커링·키보드 이동·스크롤바·접근성 트리를 브라우저가 준다. 0.3이 "직접 구현한다"고 적었던 항목이 사라진다.
- **치르는 것.** Ctrl+휠을 가로채므로 그리드 위에서 브라우저 페이지 줌이 동작하지 않는다. 텍스트 확대 요구는 `+`/`−` 키와 하단 줌 바로 받는다(§7).
- **폐기.** 그리드 빈 곳 드래그 이동(스크롤과 중복), 설정 "휠 동작" 토글과 localStorage 저장, 트랙패드 감지 휴리스틱. 휠과 트랙패드가 같은 동작을 하므로 구분할 이유가 없다 — §11 C-5는 항목째 삭제한다.
- **텍스트 선택.** 드래그가 더 이상 이동이 아니므로 칩·요약문 선택을 허용한다. 여전히 드래그 대상인 **시대 레일만** `user-select: none`. 연도 거터는 드래그 핸들 역할이 없어지므로 별도 규정을 두지 않는다(§5-10 개정).
- **URL.** `?r=kr,cn,jp,us&y=1500&s=year`로 throttled replaceState. 중앙 연도는 이제 상태가 아니라 `scrollTop`에서 나오는 **파생값**이다. 복원 시 `history.scrollRestoration = 'manual'`로 브라우저 자동 복원을 끄고 `scrollTopForYear`로 되돌린다.

## 2. §5-5A 시간축 좌표계 — 신설 (§5-5 바로 뒤)

### 5-5A. 시간축 좌표계

그리드의 모든 위치 계산은 의존성 0 순수함수 하나에서 나온다(`src/lib/timeline/axis.ts` + vitest). `suite/packages/work-core/src/core.ts`와 같은 방식이다 — 자립 단일 파일, 구조 타입, 대칭 API. 그 코드는 간트용이라 재사용하지 않고 형식만 따른다.

**도메인**

| 상수 | 값 | 비고 |
|---|---|---|
| `AXIS_YEAR_START` | −499 | 기원전 500년. 천문학적 연수(1 BC = 0) |
| `AXIS_YEAR_END` | 2026 | §11 C-2에서 컷오프를 정하면 함께 조정 |
| `AXIS_SPAN_YEARS` | 2,526 | `END − START + 1` |

**DOM 구조**

```
<div class="grid-scroller">     overflow-y:auto · overflow-anchor:none · overscroll-behavior-y:contain
  <div class="spacer">          height = contentHeight(s, viewportH)
    <정치체 밴드 레이어>          가상화하지 않는다(약 60개)
    <셀 레이어>                   뷰포트 범위 ± 오버스캔만 렌더
    <기간 막대 SVG>
    <점프 힌트>
```

**변환**

```
padTop = padBottom = viewportH / 2       -- 첫 해·마지막 해도 화면 중앙에 올 수 있게
contentHeight   = AXIS_SPAN_YEARS × s + viewportH
yearToY(year)   = (year − AXIS_YEAR_START) × s + padTop
yToYear(y)      = (y − padTop) / s + AXIS_YEAR_START
visibleYears(t) = [ yToYear(t), yToYear(t + viewportH) ]      -- 축 범위로 clamp
```

행 인덱스는 의미 레벨의 행 단위 `u`(100·10·1년)로 floor 버킷을 잡는다. 발행 청크 키는 여기서 파생되는데, **청크 파일 단위는 행 단위보다 한 자릿수 크다**(§5-2 델타) — 연도 행 → 10년 파일, 십년 행 → 100년 파일, 세기 행 → 열당 1파일. 이 변환은 `chunkKeyFor` 하나로 모은다.

**시그니처** — 전부 순수함수. 상태도 DOM 접근도 없다.

```ts
interface Axis { s: number; viewportH: number }        // s = px/년
type Level = "century" | "decade" | "year" | "month"  // month는 P1

yearToY(year: number, a: Axis): number
yToYear(y: number, a: Axis): number
contentHeight(a: Axis): number
visibleYears(scrollTop: number, a: Axis): { from: number; to: number }
visibleRows(scrollTop: number, a: Axis): { level: Level; unit: number; from: number; to: number }
levelOf(s: number): Level
clampScale(s: number, viewportH: number, level: Level): number   // S_MIN·S_MAX
zoomAt(scrollTop: number, anchorOffsetY: number, s: number, sNext: number, viewportH: number): number
scrollTopForYear(year: number, a: Axis): number        // 연도 점프·URL 복원
centerYear(scrollTop: number, a: Axis): number         // URL의 y= 파생값
railY(year: number, railHeight: number): number        // 시대 레일 — 연도 도메인 선형 매핑
railWindow(scrollTop: number, a: Axis, railHeight: number): { top: number; height: number }  // height ≥ 8px
polityAt(year: number, region: RegionId): Polity       // 밴드 약 60개, 이진 탐색
chunkKeyFor(bucket: number, level: Level): string      // 행 버킷 → 발행 청크 키
formatRowLabel(bucket: number, level: Level): string   // 표시 규칙 단일 출처(기원전 포함)
```

**줌 앵커** — 앵커 아래 연도를 고정한다. `t` = `scrollTop`, `a` = 앵커의 뷰포트 내 y오프셋, `p` = `padTop`.

```
anchorYear = (t + a − p) / s + AXIS_YEAR_START
t′         = (t + a − p) × (s′ / s) + p − a          -- viewportH 불변이면 p′ = p
```

결과를 `[0, contentHeight(s′) − viewportH]`로 clamp한다. **스페이서 height를 쓴 뒤 같은 레이아웃 패스 안에서 `scrollTop`을 대입해야** 한 프레임도 튀지 않는다(`useLayoutEffect`). 선례: 시간→px 선형 변환을 쓰는 캘린더 주간 뷰가 같은 기법을 쓴다(고정 스케일이라 코드는 재사용 불가).

`overflow-anchor: none`이 필요하다 — 브라우저의 스크롤 앵커링이 스페이서 높이 변경에 반응해 우리의 `scrollTop` 대입과 싸운다. 실제 필요 여부는 M2에서 A/B로 확인한다.

**스케일 경계**

| | 규칙 | 근거 |
|---|---|---|
| `S_MIN` | `viewportH / AXIS_SPAN_YEARS` | 전체 조망. 800px 뷰포트에서 0.32 px/년 |
| `S_MAX` | `행 단위 u × s ≤ gridH` | 한 행이 뷰포트보다 커지면 같은 해 안에서도 스크롤해야 해 비교가 깨진다 |

`S_MAX`의 귀결: 세로 344px 그리드(최소 뷰포트 320×480)에서 연도 레벨 상한이 344 px/년이 되어 **월 레벨(P1, s ≥ 400)에 진입할 수 없다.** P1에서 재검토한다.

**총 높이와 브라우저 한계**

| 레벨 | s (px/년) | 스페이서 높이 |
|---|---|---|
| 세기 하한(S_MIN, 800px 뷰포트) | 0.32 | 808px |
| 세기 → 십년 경계 | 4 | 10,104px |
| 십년 → 연도 경계 | 40 | 101,040px |
| 연도 상한 | 399 | 1,007,874px |
| 월(P1) 진입 | 400 | 1,010,400px |

P0 최대치가 약 100만 px이고 주요 엔진의 요소 최대 높이는 그보다 한참 크다 **(가정, M2에서 4개 엔진 실측 — §11 C-11)**. **P0에는 가상 원점 장치가 필요 없다.**

**레벨 전환**

변환식이 의미 레벨에 의존하지 않으므로 레벨이 바뀌어도 위치가 튀지 않는다 — 행이 다시 버킷팅될 뿐이다. 경계(4·40·400)를 왕복할 때 크로스페이드가 깜빡이지 않도록 **경계에 히스테리시스**를 둔다(확대 진입과 축소 복귀 임계값을 ±5% 다르게 **(가정)**).

**기원전**

축 내부 계산은 전부 천문학적 연수다. 표시 변환은 `formatRowLabel` 하나로 모으고, `data-model §3-4`가 이 함수의 단일 출처가 된다(§4 델타에서 기원전 세기 라벨 오류를 함께 고친다).

**검산** — M2 1단계 vitest에 그대로 옮긴다.

| # | 입력 | 기대 |
|---|---|---|
| T1 | `s=40, viewportH=800, t=0` | `visibleYears`가 축 하한에서 clamp되어 기원전 500년부터 |
| T2 | `t=1000, a=400, p=400, s=40` | `anchorYear = −474` (기원전 475년) |
| T3 | T2에서 `s′=80` | `t′ = 2000`. 재계산한 `anchorYear`가 −474로 동일 |
| T4 | `year = −499`, `s` 임의 | `yearToY = padTop` |
| T5 | `s: 39.9 → 40.1`, 같은 앵커 | `anchorYear` 불변. 행 단위만 10년 → 1년 |
| T6 | `s=4, viewportH=800` | `contentHeight = 10,904px`. 화면에 200년만 들어온다 — 전체를 보려면 `S_MIN`(0.32)까지 축소해야 하고 그때 세기 행은 32px. **§11 C-1 "전체 조망" 안이 왜 성립하지 않는지의 근거** |
| T7 | `formatRowLabel(−500, 세기)` | "기원전 501–402년". 현행 `data-model §3-4`의 "(−599~−500)"은 오류 |
| T7b | `formatRowLabel(0, 세기)` | "기원전 1년–서기 99년" — 이음매 버킷 `[0, 99]` |
| T8 | `zoomAt` 결과 clamp | 축 양끝에서 `[0, contentHeight − viewportH]`를 벗어나지 않음 |
| T9 | `chunkKeyFor(1592, "year")` | `year/1590` — 행은 1년이지만 파일은 10년 묶음 |
| T10 | `railY(1592)` vs `scrollTop` 비율 매핑 | 두 값이 다름을 확인 — 패딩 때문에 비율 매핑은 틀린다 |

## 3. 레이아웃 — 0.3에 없던 규칙

0.3 전문에 `vh`·`overflow`·`min-height`·세로 높이에 대한 서술이 **한 건도 없다**. 작은 창 문제의 절반은 여기서 나온다.

### 3-1. 세로 브레이크포인트 (§5-7 브레이크포인트 표 아래 신설)

고정 세로 크롬: 상단바 56 + 정치체 헤더 40 + 하단 줌 바 40 = **136px**. 연도 레벨에서 최소 3행(120px)을 보장하면 산술적 최소 창 높이는 **256px**이다.

폭 쪽이 더 빡빡하다. 폰에서 2열을 유지하려면 `폭 − 거터 40 − 스크러버 16 ≥ 300`이어야 하는데, 320px에서는 열당 **132px**로 §5-7의 "열당 약 150px"을 밑돈다(360px에서 152px로 성립). 따라서 **최소 지원 뷰포트는 360 × 640**이고, **320–360px 구간은 2열을 억지로 유지하지 않고 1열 + 행 시트로 저하**시킨다. 그 아래(폴더블 접힘 등)는 `/y/{year}` 카드 스택으로 유도한다.

| 창 높이 | 처리 |
|---|---|
| ≥ 600px | 현행 전부 표시 |
| 480–600px | 하단 줌 바를 접고 상단바 우측 `[− s +]`로 통합 |
| < 480px | 정치체 스티키 헤더를 1줄 24px로 축약 |

규칙: **뷰포트 높이가 최대 스케일을 정한다**(§5-5A `S_MAX`).

### 3-2. 가로 — 최소 열 폭 150px는 불변 (§5-10)

1024px 창에서 상세 패널(400px)을 열면 4열이 열당 128px가 되어 §5-7의 "열당 약 150px"를 밑돈다. 폭을 나누는 대신 **패널의 형태**를 바꾼다.

| 창 폭 | 상세 패널 | 시대 레일 | 연도 거터 |
|---|---|---|---|
| > 1440px | 우측 push, `clamp(320px, 32vw, 400px)` | 64px | 48px |
| 1024–1440px | **그리드 위 overlay** (그리드 폭·스케일 유지) | 40px | 40px |
| < 1024px | **바텀 시트** (모바일과 동일) | 우측 스크러버 | 40px |

### 3-3. 내부 스크롤 (§5-7 · §5-10)

- 상세 패널: `overflow-y: auto; overscroll-behavior: contain`.
- 모바일 바텀 시트: 반 높이 `50svh`, 전체 확장 `100dvh`, 최소 176px, 내부 `overflow-y: auto` + `overscroll-behavior: contain`. **`100vh`는 iOS 주소창 때문에 쓰지 않는다.**
- **`+N` 행 확장 → 오버레이 팝오버로 변경**(§5-3). 행 높이를 늘리면 `yearToY`가 더 이상 아핀이 아니게 되어 줌 앵커·시대 레일·URL 복원이 전부 어긋난다. **§4-4 "축은 항상 선형이다"가 여기에도 적용된다.**

### 3-4. 시대 레일 ↔ 네이티브 스크롤바 (§5-10 시대 레일 항목 뒤)

두 장치의 정의역이 기원전 500~2026으로 **완전히 같아진다**. 레일 창과 스크롤바 썸은 같은 `scrollTop`에서 파생되므로 항상 동기화된다. 레일 드래그는 `scrollTo`다.

**주의 — 레일 매핑은 스크롤 비율이 아니라 연도 도메인이다.**

```
railY(year) = (year − AXIS_YEAR_START) / AXIS_SPAN_YEARS × railHeight
```

`scrollTop / (contentHeight − viewportH)`로 매핑하면 상하 패딩 때문에 레일 위치가 연도와 어긋난다. 레일 창 높이는 `(viewportH / s) / AXIS_SPAN_YEARS × railHeight`인데 연도 레벨에서 1px 미만이 되므로 **최소 8px 보장** + 중앙 표시선. 모바일 우측 16px 스크러버도 같은 함수를 쓴다.

**네이티브 스크롤바는 그리드 컨테이너에서 숨긴다**(`scrollbar-width: none`). 정보가 100% 중복인 것에 더해, 연도 레벨 `s=399`에서 썸의 이론 높이가 1px 미만이라 브라우저 최소값(약 20px)으로 강제되고 그 순간 썸 위치가 실제 스크롤 위치와 어긋난다 — 1px 드래그가 수십 년을 건너뛴다. **깊이 줌할수록 못 쓰는 컨트롤이 된다.** 상세 패널·바텀 시트 등 다른 스크롤 영역의 스크롤바는 그대로 둔다. 레일에는 드래그 가능하다는 시각 신호(호버 시 확대, 커서 `grab`)를 준다.

### 3-5. 정치체 스티키 헤더 — 조건부로 공짜 (§5-10 해당 항목)

`position: sticky`로 JS 계산이 0이 되지만, 다섯 조건 중 하나라도 어기면 **조용히 깨진다**.

1. 정치체 밴드를 절대배치 박스(`top: yearToY(시작)`, `height: (끝−시작) × s`)로 렌더하고 그 **자식**을 `sticky; top: 0`으로 둔다.
2. 밴드에 **`overflow: hidden` 금지** — 그 자체가 스크롤 컨테이너가 되어 헤더가 영원히 고정된다. 칩 클리핑은 별도 셀 레이어에서.
3. 스페이서·밴드 조상에 **`transform` / `filter` / `will-change: transform` 금지** — transform 조상이 sticky의 컨테이닝 블록을 가로챈다. §8의 "이동은 transform" 폐기의 두 번째 이유다.
4. 밴드 높이 < 헤더 높이 + 8px이면 헤더를 렌더하지 않고 색 띠만 표시한다(대한제국 1897–1910은 세기 레벨 `s=2`에서 26px).
5. **밴드 레이어는 가상화하지 않는다** — 약 60개뿐이므로 전부 렌더한다. 뷰포트 상단을 덮는 밴드가 언마운트되면 헤더가 사라진다.

조건 4로 헤더가 숨는 구간에서도 "이동 중에도 어느 시대인지 항상 안다"를 지키려면, **스크롤 컨테이너 밖 열 헤더에 `polityAt(뷰포트 상단 연도)` 파생 표시**를 둔다. sticky(자연스러운 밀려남)와 파생 표시(끊김 없음)의 역할 분담이지 중복이 아니다.

### 3-6. §11 C-6 광고 — 전제는 무너지되 결론은 유지

"그리드는 네이티브 스크롤을 쓰지 않으므로 인피드 광고 자리가 없다"는 근거가 무효가 된다. 결론(그리드 밖 고정 슬롯만)은 유지하고 **근거를 셋으로 교체**한다.

1. **축 왜곡 금지(§4-4)와 정면 충돌.** 행 사이에 광고를 끼우면 `yearToY`가 아핀이 아니게 되고 줌 앵커·시대 레일·URL 복원이 어긋난다.
2. **줌과 호환되지 않는다.** 광고 슬롯 높이는 px 고정인데 축의 모든 것은 `연수 × s`다. 레벨이 바뀌면 어느 행에 붙어 있었는지 정의할 수 없다.
3. **가상화와 뷰어빌리티 측정이 충돌한다.** 뷰포트 밖 행이 언마운트되므로 슬롯이 반복 생성·파괴된다.

하단 앵커 광고 금지는 그대로. `/y/{year}` 페이지와 모바일 행 시트 내부는 네이티브 스크롤이므로 인피드가 자연스럽고, 이는 현행 C-6이 이미 허용한 위치다.

### 3-7. §9 지표 재정의

"세션당 연도 이동 수 = 드래그·점프로 뷰포트 중앙 연도가 바뀐 횟수"는 연속 스크롤에서 그대로 셀 수 없다. **`scrollend`(미지원 브라우저는 디바운스) 단위로 중앙 연도가 5년 이상 바뀐 사건 수 (가정)**로 재정의한다. 대신 그리드가 진짜 스크롤 컨테이너가 되어 **스크롤 깊이·체류 구간을 표준 방식으로 측정**할 수 있게 된다.

## 5. `docs/data-model.md` 델타

### 5-1. §3-4 표시 변환 — 기존 오류 수정

현행:

> 세기 라벨: `Math.floor(y / 100) * 100 + '년대'`. 기원전은 "기원전 500년대"(−599~−500).

`Math.floor(y/100)*100`의 버킷은 `[−600, −501]`, `[−500, −401]` … 이다. 괄호의 `(−599~−500)`은 어느 floor 버킷과도 일치하지 않는다. 그리고 `−500`으로 라벨링되는 버킷의 실제 범위는 `[−500, −401]` = **기원전 501년~기원전 402년**이라 "기원전 500년대"라는 이름과도 어긋난다.

**개정안**: **균일 floor 버킷은 그대로 두고 라벨만 고친다.** 기원전 구간만 원점을 옮겨 "기원전 5세기 = 500~401년"에 맞추는 안은 채택하지 않는다 — 축 어딘가에 이음매가 생기고 `visibleRows`의 O(1) floor 계산에 분기가 붙는다.

기원전 버킷은 이름 대신 **범위 표기**를 쓴다 — "기원전 501–402년". 기원전 구간 버킷은 `[−500,−401]` … `[−100,−1]` **다섯 개뿐**이라 범위 표기가 장황해질 일이 없다. 이음매 버킷 `[0, 99]`는 "기원전 1년–서기 99년"으로 정직하게 쓴다(데이터가 가장 희소한 구간이라 비용이 사실상 0). 서기는 현행 "1500년대" 유지. 표시 규칙의 단일 출처를 `axis.ts`의 `formatRowLabel`로 지정하고 이 문서는 그 함수의 명세로 둔다.

### 5-2. §6-1 청크 파일 단위 확대

**문제.** 네이티브 스크롤은 관성이 있어 드래그 모델보다 축을 훨씬 빠르게 훑는다. 연도 레벨 `s=120`·뷰포트 800px이면 화면에 6.7년이 들어오고, 초당 2,000px 관성이면 **초당 약 17개 연도 청크**를 요청하게 된다. 현행 `events/{region}/year/1592.json`은 파일당 1년이다.

| 레벨 | 현행 | 개정 | 비고 |
|---|---|---|---|
| 연도 | 1년 (`year/1592.json`) | **10년 묶음** (`year/1590.json` = 1590–1599 전량) | 요청 수 1/10 |
| 십년 | 10년 | **100년 묶음** (`decade/1500.json` = 1500–1599) | 중요도 ≥4 필터라 더 작다 |
| 세기 | 100년 | **열당 1파일** (`century/all.json`) | 26개 세기 행 × 중요도 5 |

- **요약문은 처음부터 청크에서 분리한다.** 현행 §6-1은 "넘으면 요약문을 빼고 `events/detail/{id}.json`으로 지연 로드"를 예비책으로 두었는데, 이것을 **기본값으로 승격**한다. 근거: 요약문이 필요한 시점은 언제나 한 번 더 탭·클릭한 뒤다 — 셀의 칩에도, 모바일 행 시트의 사건 목록에도 요약문은 나오지 않고 상세 패널을 열어야 비로소 필요하다. 처음부터 빼두면 청크 크기가 사건 수에 선형으로만 반응해 예측이 안정되고, 근현대 밀집 구간에서 한계를 넘어 전량 재발행하는 위험이 사라진다. 청크에는 제목·관점 명칭·중요도·날짜·카테고리·지역만 싣는다.
- 크기 목표 "연도 청크 1개 ≤ 20KB gzip"은 **요약문을 뺀 10년 묶음 기준으로 재해석**한다 **(가정, M1 발행 후 실측)**.
- 프리페치: 스크롤 방향·속도 기반으로 진행 방향 **±1.5화면 (가정)** + 인접 레벨 1단계. 관성이 있으므로 예측 거리가 기존보다 길어야 한다.
- 지나간 구간의 인플라이트 요청은 `AbortController`로 취소한다.
- §5-7 성능 예산 "첫 뷰포트 JSON ≤ 50KB"는 유지 가능 **(가정: 폰 2열 × 10년 묶음 2개 ≈ 40KB)**.

### 5-3. §7 열린 사항

"레벨별 청크의 중요도 임계값을 M1에서 확정" 항목에 **"청크 파일 단위도 함께 확정"**을 추가한다. 둘 다 바뀌면 전량 재발행이 필요하다.

### 5-4. 변경 없음

천문학적 연수 · 관점별 명칭(`event_names`) · 지역별 중요도(`event_regions`) · 3개 의미 레벨 발행 · 원천과 파이프라인. **이번 전환은 데이터 모델 본체에 아무 변경도 요구하지 않는다.**

## 8. 구현 순서 (M2)

`axis.ts` + vitest → 스크롤 컨테이너·스페이서·연도 거터(`s=399` 약 101만 px 실측) → 가상화·오버스캔·rAF 코얼레싱 → 줌(`zoomAt` + height·scrollTop 동시 쓰기) → 레벨 전환·히스테리시스·프리페치. **여기까지가 임계 경로.**

**1단계는 브라우저 없이 완결되므로 M1 후반에 미리 시작할 수 있다.**
